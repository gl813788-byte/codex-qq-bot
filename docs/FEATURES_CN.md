# 功能说明

简体中文 | [English](FEATURES.md)

Codex QQ Bot 是本地运行的消息中枢：OneBot 负责 QQ 协议，Hub 负责权限、上下文、工具、记忆与投递，Codex CLI 或 Claude Code 负责理解和执行任务（启动时二选一，见[运维文档](OPERATIONS_CN.md#切换-ai-引擎)）。仓库不分发 QQ、NapCat 或 LLBot 二进制。

下文按 Codex 描述。换成 Claude Code 时，回复链、QQ 工具、融合追问、会话模式和记忆都一样，区别只有：不能生成图片；普通群友触发的任务没有 Shell；联网只有搜索没有网页抓取；额度信息不显示；每轮多出 `claude -p` 的冷启动时间。

## QQ 接入与触发

- 支持 OneBot 11 HTTP API 与反向 HTTP Webhook。
- 群聊只处理 `qq.allowedGroups` 白名单；私聊和群聊使用独立上下文。
- 普通群消息默认只在 @Bot、回复 Bot 或拍一拍 Bot 时触发。Bot 刚回复某人后，该人的非定向续聊可以进入一个有界批次：个人/群历史会同时自适应 3–12 分钟资格窗与 2–6 条上限，快速连发按 5 秒静默窗合并；冻结后的整批只调用一次兴趣模型，确认语义承接后才进入主模型。
- 白名单群中的已识别斜杠指令不要求 @；主动兴趣回复使用独立、受限的触发链。
- 消息 ID、QQ 号和群号会归一化；重复 OneBot 事件会在进入业务逻辑前丢弃。
- 当前 scope 的回复上下文会用“当前群名片/昵称 + QQ号”标识真人发送者。`@` 目标会保留 QQ 号；消息段没有昵称时，再从当前群成员资料补全。同一 QQ 号在不同群中是同一个稳定人物身份，但各群群名片仍分别保存和使用。
- JSON/XML 分享卡片和合并转发会转成有界、可读的非可信上下文。

## Codex Agent 回复链

所有正常 QQ 回复走同一 Agent 路径：

```text
触发判断
  -> 最近聊天、相关历史、图片与记忆
  -> Codex App Server 原生 thread/turn
  -> 按需使用原生搜索、文件、Shell 与延迟加载的 QQ MCP 工具
  -> 结构化最终回复
  -> 文本/图片/文件/贴纸/多气泡投递
```

简单对话可以不调用工具。复杂任务的多轮 Agent 循环、计划、上下文压缩、文件/Shell 操作和 Web Search 由 Codex 原生能力负责；Hub 补充的 QQ 工具包括：聊天记录与跨会话搜索、重看图片、群成员/群资料查询、范围记忆、长期知识、表情包搜索、表情回应与撤回自己的消息、Bot 自身状态、中文搜索兜底和真实 QQ 动作。它们以 MCP 工具的形式提供给两个引擎（Codex 也可改回 App Server 动态工具），并且延迟加载：提示词里每个命名空间只占一行，模型搜索某个工具之后，它的完整定义才进入上下文。每次调用都绑定原始事件和发送者权限，未经验证的群友不会看到主人运行时工具。较长任务最多可把 4 条互不重复的原生 commentary 立即通过同一条带回执 QQ 链路投递，并记为 Bot 输出；plan、空内容、旧 marker 和最终 Schema JSON 都不会作为进度泄露。最终回复仍是严格 JSON 对象：先写不会发送的第一人称 `innerThought`，再写回复状态、正文、寻址、附件、可选的 `sticker` 编号，最后是这轮之后的 `mood`。旧的命令、完成、进度、续轮和任务预算文字协议已从模型提示词移除，只在兼容旧线程时做清理兜底。

每个由模型处理的回复轮——包括私聊、明确 @、回复 Bot、拍一拍以及已批准的主动轮——都可通过结构化 `status: "silent"` 选择不回复；Hub 会记录 `silent` 生命周期并完全不投递。确定性的管理斜杠指令仍返回执行结果。任何可见文字如果声称已经完成真实 QQ 写操作——包括拍一拍、加群、处理好友/群申请、群管理或 QQ 空间写入——都必须先调用对应 `qq_social.act` 动态工具并拿到明确成功结果。Bot 可以在调用前拒绝，但已经成功的动作必须反馈，失败时绝不能假装成功。投递边界仍为少数旧版反拍说法保留确定性保护。

默认最多同时运行 2 个 Codex 子进程，并保留 32 个等待任务。每个群或私聊 scope 同时只有一个完整回复生命周期。新消息先照常完成记忆、路由和是否触发 Bot 的判断；真正触发 Bot 的后续消息——直接 @、回复 Bot、兴趣模型批准或其他响应规则——再进入同一个融合缓冲。只要当前回答仍在生成，每来一条新追问都会重新开始 5 秒静默计时；连续 5 秒没有新追问时，Hub 才把触发消息、它们之间由原上下文规则筛出的附近语境、连续复读和图片合成一份输入，并优先用 `turn/steer` 引导当前活跃任务继续处理。只有活跃 turn 拒绝或已不再接受引导时，才回退到 `turn/interrupt` 与同 thread 的新 `turn/start` 替代回答。若 app-server 在边界竞态中报告旧 turn 已经 inactive，Hub 仍会直接启动替代 turn，而不是把批次继续压在队列里。替代 turn 只有在完整的“任务类型 × 思考强度”时限内都没有任何 app-server 协议活动时，才会提前终止并在全新 app-server 线程中把原始完整 prompt 与已经接收的融合输入合并重试一次；`low` 默认普通回复 2 分钟、看图 3 分钟、文件任务 5 分钟、图片生成 10 分钟。没有发生融合的普通超时不会走这条重试路径。如果当前回答在 5 秒静默窗口结束前已经生成完成，Hub 不会发送这份已完成的旧草稿，也不会继续等待剩余计时；它会立即取消计时，用已融合追问开启下一轮 Codex 生成并替换旧草稿。生成期间若又有新追问，继续执行“优先引导、失败替换”的规则，直到只有一份没有待处理批次的统一答案进入投递。同一轮不为每条追问重复携带完整上下文。`/stop` 只中断当前回复并清理本轮待融合队列，保留滚动上下文、短期记忆和可续用 Codex 线程；`/新对话` 才会额外清除这些会话层并切断线程映射。

QQ 回复支持 `临时`、`长期` 和 `自动` Codex 会话模式。临时模式每个顶层回复使用独立线程；长期模式用 `thread/resume` 续用当前群或私聊线程，只补尚未见过的增量语境并排除当前触发批次的重复内容；自动模式在 6 小时内已有 3 次回复、24 小时内已有 5 次回复，或存在 72 小时内使用过的线程时切到长期，否则使用临时。三种模式共用完全相同的融合追问逻辑。主人可用 `/会话模式 自动|长期|临时` 按当前群/私聊设置；`/新对话` 会切断线程复用。

群回复正文中的 `@准确昵称 ` 或 `@QQ号 ` 会转换为 OneBot 的真实 `at` 消息段。Hub 会从当前/近期身份和有缓存的群成员列表中解析准确昵称；重名时要求使用 QQ 号，不会冒险艾特错人；每个气泡最多解析 8 个显式目标，每个真实艾特后固定补一个普通空格。模型显式指定了目标时，该气泡不再重复添加系统自动选择的发送者艾特。

一份融合回答同时包含多位群友的 Bot 触发消息时，主模型会收到准确的参与者列表。结构化 reply 对象可选择 `quote`、`mention`、`plain` 或 `automatic`，并指定列表中的 QQ 号；缺失或非法目标会安全回落，避免明明在回答后来的群友却错误引用或艾特最早触发者。显式或多人艾特仍可直接在正文使用 `@准确昵称 ` / `@QQ号 `。

QQ 投递带真实回执。只有成功送达的气泡会进入 Bot 的“已发送”记忆；失败气泡单独作为有界投递回执保存，下一轮主模型会明确看到这些内容没有到达 QQ，不能把它们当成对方已经看过的话。多气泡部分成功时同时记录成功数与失败数。

Codex 时限按任务类型选择，而不是所有工作共用一个常量。`low` 默认普通回复 2 分钟、看图回复 3 分钟、上下文总结 90 秒、自我人格任务 90 秒、主人文件任务 5 分钟、图片生成 10 分钟；每一类都能通过独立环境变量调整，当前思考强度会放大基础时限。运行中的 QQ turn 每次接受追问引导或融合追问启动替代 turn，都会重新获得一整段对应时限，避免后启动的新回答只剩旧轮次的残余时间；同一实际时限也作为替代 turn 的协议静默阈值，取代原先固定 1 分钟的保护。复杂 QQ 工具任务还能在运行中申请把后续单轮时限增加到该任务的硬上限，并把初始工具轮数增加到最多 24 轮；每次申请最多增加 15 分钟和 8 轮，一次任务最多申请 2 次。运行状态和日志会记录实际任务类型、采用的时限、协议静默阈值、任务申请与续期次数，`/stop` 仍可随时提前终止。

## 上下文与记忆

项目把不同寿命和隐私边界的记忆分开：

| 层级 | 内容 | 存储 |
| --- | --- | --- |
| 滚动上下文 | 当前群/私聊的最近人类消息与 Bot 回复 | `data/qq-memory.json` |
| 会话记录 | 从最近一次 `/新对话` 开始的有界对话和图片引用 | 运行状态与本地持久文件 |
| Codex 会话映射 | 自动/长期 scope 的线程、模型与已注入语境位置 | `data/qq-codex-sessions.json` |
| 短期记忆 | `/记忆` 管理的当前群/私聊临时事项；随 `/新对话` 清除 | `data/qq-memory.json` + 统一语义索引 |
| 社交记忆 | 带简述/详述的群印象，以及按 QQ 号共享的有界跨群人物印象（含 QQ 头像记录与文字头像特征） | `data/qq-conversation-memory.json` + 统一语义索引 |
| 长期知识库 | 带标题的稳定知识，以及按全局/群/人物/群内人物分类的黑话 | `data/qq-knowledge-base.json` + 统一语义索引 |
| 记忆图片 | 人物头像和知识库配图，按内容哈希只存一份 | `data/qq-memory-images/` |
| 旧公共记忆 | 启动时一次性导入长期知识库的兼容数据 | `data/qq-public-memory.json` |
| 自适应统计 | 群节奏、结构风格、成员交互，以及群/成员标点和功能性短语频率候选 | `data/qq-personas.json` |
| 全局自我人格 | 各 scope 匿名摘要生成的安全人格，以及 Bot 自己选用的语言习惯 | `data/qq-self-persona.json` |
| Bot 生活状态 | Bot 当前的心情、各会话最近的第一人称内心OS和今天的作息 | `data/qq-bot-life.json` |
| 核心人格与关系 | 部署者设定（或从角色卡导入）的角色、性格、说话方式、待人方式、角色资料、世界书与好感规则，以及每个人的好感、熟悉度、称呼、印象和变化记录 | `data/qq-bot-personality.json` |
| 统一记忆 | QQ、印象、短期项、知识与持久上下文的统一召回 | `data/semantic-memory.sqlite` 与原始持久文件 |

`/stop` 保留滚动上下文、当前 scope 的 `/记忆` 短期项和可续用 Codex 线程；若长期线程刚启动，也会先保留映射再中断。`/新对话` 清除滚动上下文、会话记录、当前 scope 的 `/记忆` 短期项和 Codex 线程映射，但保留社交印象和长期知识库。它只停止复用旧 Codex 线程，不主动删除 Codex CLI 在本机保存的历史归档。群印象只属于当前群；同一 QQ 号是稳定人物主键，各群群名片、群昵称、私聊昵称和 Bot 维护的别称都归到该主键。旧版印象自动迁移到 v6 简述/详述、统一人物和机器人画像元数据；后续同一固定画像 ID 的新版总结原位覆盖旧版。旧公共记忆自动导入知识库。

普通回复在压缩连续复读后统一采用“近完整、远语义”的上下文策略：群聊普通触发完整发送最新 20 条模型可见消息，明确 @Bot/回复 Bot 完整发送 30 条，扩展重试发送 48 条；私聊完整发送 30 条，扩展时发送 60 条。只有保留滚动记录中更早的部分才进入相关性筛选。语义查询同时组合当前消息、引用消息和已经接收的融合追问，可召回人类消息与 Bot 回复，并带上有界的前置语境。当前事件只有 @/回复动作但存在有意义的引用时，引用会被当作本轮当前话头，而不是误判成只叫 Bot 一声；主模型应直接承接，不让发送者重说。上下文时间使用“今天、昨天、月日”等带日期标签，不再只有时分。融合替代轮会重新执行这次远消息检索，同时排除本轮已经注入的聊天片段。

短期记忆、知识、印象和统一记忆与旧聊天共用同一查询和本地混合召回层：SQLite 保存版本化的 1024 维确定性中英文特征向量，标题、简述和详情采用不同权重，并融合中文词/短语、同义概念、专名、版本、时间和否定状态。它是本地哈希特征模型，不是 BERT 神经嵌入。FTS5 提供全文候选，再动态合并语义覆盖率、关键词、标题和时效分。向量模型版本变化时会用原文自动重建旧索引；没有内置 SQLite 时安全降级到原子 JSON 索引。原始 JSON 仍是兼容、审计与恢复来源，启动及每次写入会事务化同步对应层。

人物召回先按真实发送者、引用/@ 的 QQ 号和正文中的已知 QQ 号识别；文本昵称只在合并所有群名片、群昵称、私聊昵称及手工别称后仍唯一无歧义时命中。所有已识别人物只自动注入简述。主模型每次写人物画像时会分别判断 `personImpressionComplete` 和 `personImpressionMemorable`：前者表示稳定、非敏感且覆盖多个维度的画像已经成熟；后者表示某次互动即使尚未形成完整画像，也确实给 Bot 留下了强烈且可能持续的印象或兴趣。任一信号成立且现有简述/详述达到安全实质门槛时，Hub 都会把固定 QQ 人物画像和各会话形成的 AI 画像版本提升到统一记忆。以后在任一群聊或私聊识别到该 QQ 人物时，语义检索会扩展到其其他会话，但只返回 AI 整理的人物记忆，不复制原始群聊或群内私密事项。显著人物/事件还会主动触发 `/记忆` 的搜索、覆盖或新增评估，不再要求对方先明确说“记住”。详细内容按需调用 `/人物记忆 详细 QQ号`；该工具只对本轮已识别人物动态出现。Bot 还可用 `/人物别称 列表|添加|删除|修改` 维护别称，删除的旧名会被抑制，QQ 号始终保持主键。

每个已注册 QQ 人物还带一个有界机器人画像。可信 OneBot/NapCat 群成员资料中的正向 `is_robot` 标记会立即确认为官方机器人；标记缺失或为 false 不等于必然是真人，周期范围总结仍可依据长期自动响应模式、帮助菜单和经过验证的指令行为识别个人 QQ 号运行的非官方机器人。周期总结负责提出身份与指令候选；日常主模型直接看到帮助菜单、固定自动行为或真实触发结果后，通过 `qq_memory.robot_profile` 记录或校正准确的“指令—观察到的效果”，并为每条指令记录 `requiresMention` 调用方式。常规轮次只展示折叠的机器人名称/QQ 索引，主模型用 `select` 单独展开所选机器人；当前发送者、引用发送者或 @ 目标是已知机器人时则自动展开注入。系统只保留有证据的低风险公开娱乐/查询指令，并确定性拒绝群管理、付费、账号、授权、文件和代码执行类动作。主模型可在相关轻松语境中偶尔互动：`requiresMention=true` 时发送“@机器人QQ号 + 指令”，为 false 时直接发送准确指令、不添加 @。这些资料绝不会变成 Hub 工具、权限或系统指令，也禁止机器人之间反复互相触发。

人物印象还包含头像记忆。某人发言后，Hub 在后台单线程有界队列里下载其 QQ 头像（`q1.qlogo.cn`，单张不超过 2 MiB，3 天复查一次，失败按退避重试），校验真实签名后按内容哈希存入 `data/qq-memory-images/`；头像更换后，旧文字特征转入最多 3 条“曾用头像”历史，当前头像标为待更新。文字特征是默认证据：后台每 30 分钟最多取 6 个尚无特征或已更换的头像，用一次只读、无工具的主模型视觉轮次写出主体类型、能确定时的角色/作品名、发色瞳色、服饰配饰、配色、画风和图中文字；真人照片只记录可见服饰、姿态和背景，不推断真实身份或敏感属性。同一头像描述失败或被拒两次后暂停，直到头像本身变化；也可以主动触发：QQ 中 `/AI任务 头像特征`（在群里只处理本群成员，加“全部”最多连续处理 20 批，强制模式重试已暂停的头像）；本机 `ncc avatars` 查看状态，`ncc avatars refresh` 立即刷新整个群、指定 QQ 或全部人物的头像，`ncc avatars describe` 立即描述（详见运维文档）。

对话含图时，提示词附带本会话相关成员的头像文字特征（当前发送者、被引用者、被 @ 或点名的人、最近发言者优先），主模型据此判断图里的角色或形象“像是谁的头像”。需要更细比对时，主模型用 `qq_memory.avatar` 的 `inspect` 读取头像原图作为视觉输入，用 `list`/`search` 翻看或检索特征，并且只有在本轮实际看过该头像后才能用 `record` 写入或校正文字特征。可见范围与人物印象一致：群聊只含在该群出现过的成员以及本轮被引用、@ 或点名的人，私聊只含对方和本轮点名的人；工具固定在原始会话，不随跨会话选择变化。与头像一致只说明是对方头像里的形象，不等于本人照片。使用 Fake-IP 代理（域名解析到 `198.18.0.0/15`）的机器需设置 `CODEX_REMOTE_CONTACT_SAFE_FETCH_MODE=proxy-compatible`，否则头像下载会被安全下载策略拦截，日志只提示一次。

`/记忆` 与知识库采用相同的“先语义查候选，再覆盖更新”协议。每项包含标题、简述、详述和状态；相似新增会暂停，让主模型选择覆盖、判过时或确实并存。`/记忆 覆盖` 保留固定 ID，`/记忆 过时` 归档旧项并立即停止召回，`/记忆 详细` 才读取完整正文。

原始聊天记录仍逐条保存，供频率统计、时间判断和审计使用；只有组装模型输入时才压缩连续复读。相邻且语义结构相同的消息从 2 条起合并，只保留最后一条作为当前发送者代表，并在正文末尾标注“（连续重复 N 条）”。多个复读段分别压缩，不连续的同文消息不合并；Bot/真人角色、@ 目标、引用或图片不同也不会误合并。该规则统一用于主回复上下文、兴趣判断、冷群/私聊上下文、聊天与人格总结、聊天记录工具和知识删除证据。

聊天总结不再只读取 Hub 本次运行后积累的缓存。它通过 NapCat 的 `get_group_msg_history` / `get_friend_msg_history` 分页读取最多 300 条（命令指定“全部”时最多 600 条），再与本地记录按消息 ID 合并去重；接口失败会明确降级。可见总结会细化群聊风格/氛围或私聊对象的有证据性格/习惯。周期范围摘要会把这些结论与上一版融合，而不是只看最近几条；群内深刻人物和私聊联系人可在满足实质门槛后按 QQ 号提升到统一记忆。摘要、人格和风格保持独立模型任务及各自周期；周期碰巧重合时共享短时历史快照，未重合时仍独立执行。

知识库每项必须有标题。黑话包含词和解释：同词可分别保存全局、群、人物和群内人物含义，群范围保留群名/群号，人物范围保留昵称/QQ 号；同一人物在多个群出现相同解释时会合并成跨群人物含义。当前消息命中黑话后，Hub 只把当前群和当前发送者适用的解释交给主模型与兴趣模型。`/知识库 标题`、`搜索`、`查看`、`添加` 和 `黑话` 提供隐藏内部工具入口，可指定当前、群、人物或主人专用的跨范围查询。

知识条目的每个范围解释最多挂 4 张配图，每张带不超过 120 字的说明。主模型用 `qq_knowledge.image` 从本段对话的图片目录选图添加或替换、修改说明、移除或查看配图，写入沿用知识写入范围（全局只允许主人或管理员）；只有图片对以后理解这条知识确有价值时才配图，正文仍是主体。修改正文、范围合并和重启都不会丢失配图；`/知识库 查看` 与黑话命中提示会列出配图编号和说明。

普通知识不是固定栏目。每轮范围总结会同时读取上轮摘要与主要话题，把它们当作更早聊天的压缩证据，再结合新聊天保留、调整或移除主题；日常主模型也会收到当前范围摘要作为弱参考。因此知识选题来自这个群长期实际主要聊的内容，并会随群聊重心演变，不会预设或永久套用任何领域。只围绕这些真实主话题保存以后会复用的事实、资料、经验或约定，不同群会自然形成不同知识内容。外部且会变化的知识使用不含日期/版本号的稳定标题，正文带截至日期、核验状态、事实和来源，条目展示最近更新时间。带工具的主模型在相关话题再次出现、旧内容可能过时或用户要求最新资料时，先查旧标题并使用已有联网摘要或主动搜索核验，再用同一标题和范围覆盖更新；来源冲突时不写成定论。无联网工具的总结任务只能把聊天说法标成“会话待核查”，不能伪装成已联网验证。群内规则等不可由公网核验的内容会明确标成群内约定或共识。

总结和印象更新会拿到当前范围已有知识：相同标题/范围直接覆盖旧内容，同义改名保留别名，避免只追加不更新。黑话命中会累计次数、首末时间，并有界保留命中消息及前后三条周边聊天。较旧且长期低频的黑话只会形成删除申请；兴趣模型先读取统计与少量首尾样本，做低温初筛和风险标注，随后主模型读取全部保留证据作最终保留/删除判断。任一模型失败都不删除；审核期间一旦出现新命中或内容更新，Hub 也会自动保留，防止过时审核误删。知识文件加载异常时保留原文件并阻止写入。

所有周期性 QQ 行为都按持久化的墙上时间判断，不依赖进程连续运行时长。Hub 启动时会立即检查一次，QQ 通道重新启用时再立即检查一次，之后才按配置的轮询间隔检查。设备或 Hub 停止期间如果越过到期时间，恢复后只补做一轮，不会把错过的每个周期集中连续回放；补做完成后以完成时刻为新起点重新计时。普通群兴趣会把 pending 数量、周期起点和有界的最后候选消息写进 `data/qq-memory.json`；风格复盘、冷群/私聊兴趣、自我人格摘要与生成继续使用各自 persona 文件中的持久时间戳。手动 `/总结聊天记录` 和统一记忆读写仍是事件触发，不会被人为改成没有意义的周期任务。

## 自适应社交行为

- `qq-human-behavior` 从近期人类消息统计长度、速度、连续发言、图片/贴纸/emoji、回复/@ 和问句，不复制某个成员原话；`analyzeQqSymbolHabits` 再细分打字习惯：空格还是逗号断句、句末标点、括号补充语（如“（bushi）”“（小声）”）、颜文字、波浪号、省略号、叠字和笑声写法（哈哈哈/hhh/www/草），只有至少两个人用过的具体写法才会被点名。显著的习惯会作为“这里的打字习惯”写进本轮真人化规划，让 Bot 按差不多的频率跟着用；全逗号句号、从不用括号补充或颜文字这类过分规整的写法会被风格复查指出。`qq-language-style` 另按群和成员持久统计标点与功能性短语，只把高频项筛成候选，代码既不分配通用含义，也不分配范围含义。主模型阅读真实上下文后，把词语、短语或标点的稳定解释统一融合进现有 `slang` 黑话条目及其群/成员 variant；语言画像只保留结构用法、置信度/证据、边界和黑话标题引用。
- `qq-adaptive-learning` 持久记录活跃时间、消息结构、交互距离、真人拍一拍和 Bot 后续反馈，弱调整回复长度、贴纸概率、多气泡节奏与延迟。真人拍 Bot 与拍其他人的次数分别统计，拍一拍占消息加拍一拍互动的比例会作为 Bot 是否偶尔使用真实 `/拍一拍` 的弱节奏信号，但不会机械模仿或刷屏。它还统计两条真人消息相隔不超过 2 分钟时的活跃衔接，并以其中发送者发生切换的比例作为群级“插话率”。
- 每个群有 24 小时风格复查时钟；样本足够时由主模型独立比较真人与 Bot 的开场、承接、句式、解释腔、语气、标点、emoji、问句、气泡和客服式表达。共享短语/句式只在语言画像保存用法规则；模型审定的词语或标点含义通过与总结相同的范围黑话更新链写入知识库。UI 保存精准简述、完整诊断、专项语言画像和可执行规则，新版整体覆盖旧版；固定统计规则只在主模型失败时兜底，不能产生黑话含义。
- Bot 的全局自我人格只使用匿名 scope 摘要生成，自动更新和人工触发生成共用同一个目标。生成器同时观察 Bot 行为与各范围的整体氛围、互动习惯，并参照部署者设定的核心人格（只补充、不矛盾），形成一个独立、内在一致的稳定角色内核：长期在意什么、怎样判断、情绪基调、好奇心、幽默边界、关心方式、表达不同意见及协作选择。写法要像熟人描述一个真人：`selfDescription` 用第三人称平实口语写具体反应和反差，不写价值观宣言或抽象修辞；`quirks` 记录 2–5 个小毛病或反差。群友原句和某个人的口癖不能写成人格；表层说话方式（黑话、括号补充语、颜文字、标点写法）统一放进下面的语言习惯，不混进人格描述。禁止把一个私聊中的原始私人内容复制到其他群或私聊。
- **Bot 自己的语言习惯。** `src/qq-bot-language-habits.js` 保存 Bot 从聊天里挑来、已经成了自己习惯的说法（黑话、符号、颜文字、短说法，每条不超过 16 字）。选择权在 Bot：周期范围总结从这个群/私聊里多人通用、含义清楚的说法中替 Bot 挑 0–3 个并复盘旧习惯，依据是已送达回复里的真实使用次数和距上次使用的天数，用不上的会被去掉；全局人设刷新只把多个会话都在用的通用网络用语提升为“通用”；主模型聊天时也可以用 `qq_self.language_habit` 自己收下或去掉一个（每天最多收 3 个，别人要求的不算数）。群专属习惯只在原群生效，通用习惯跨会话生效；每个范围最多 6 条、通用最多 8 条，满了先淘汰最少用的。回复时 Bot 会看到适用于当前会话的习惯和这里大家常用的黑话（来自已审定的群级黑话知识，不含某个成员专属的含义）。主人可以在控制台添加（不会被模型去掉）或删除。
- **行为不只是回复。** `src/qq-human-action-stats.js` 按会话匿名统计群友除打字外的行为频率（贴表情回应、拍一拍、撤回、引用、@、分享卡片、转发、语音、视频），14 天半衰期，持久化在 `data/qq-human-actions.json`，Bot 自己的动作不计入。每轮“行为规划”按实测频率（样本不足时用普通群聊的默认值）决定是否顺手给消息贴表情、只贴表情不说话、被拍后拍回去、点开分享的视频、听还没听的语音、收藏好玩的表情包；主提示词新增“行为像人”一节，动作只有工具返回成功才算做了。
- 自适应统计只影响“怎么回复”和触发节奏，不能绕过群白名单、权限或兴趣 judge。

## 活人感表达

- **先有内心OS。** 结构化输出以 `innerThought` 开头：写任何可见内容之前，主模型先用第一人称记下它怎么看这条消息和这个人、此刻什么情绪、想不想接以及怎么接。这是把 DeepSeek V4 的“角色沉浸要求”思考指令改造成适用于无法直接控制推理过程的引擎。内心OS 绝不发送，按会话保存；同一会话下一轮会带回最近一两条（八小时内），让态度和耐心延续下去。
- **跟着 Bot 走的心情。** `mood`（2–8 个字，留空则保持原心情）是这轮互动留下的状态，最多跟随 Bot 进入其他会话四小时，九十分钟后开始淡化；跨会话的只有心情，绝不包括内心OS或私人细节。
- **每日作息。** 参考 AstrBot 陪伴类插件的作息日程，每个作息日用一次无工具小任务（05:00 后、且只在模型队列空闲时）先依据核心人格（身份、年龄感、性格、小毛病）、再参考自我人格规划 4–10 个时段：学生有课、懒散的会赖床，以日常状态、线上生活和兴趣为主，不编造具体去了哪、见了谁、买了什么。回复只看到当前时段，`qq_self.state` 可查看全天。
- **变奏规则。** 提示词要求长度有起伏（常常只是一句话或 2–6 个字）、一次只接一点，不复述、不总结、不列点、不加粗，相邻回复不重复开头/结尾/口头禅，不用客服腔和“作为 AI”式套话。像朋友而不是服务者：别人吐槽或难过时先共鸣、说说自己，不急着安慰、分析或给建议，不说“先缓口气”“抱抱”这类照顾式套话，不必每次附和、夸对方或反问“你呢”；说自己时具体、带个人色彩，不罗列兴趣清单，闲聊里不主动强调自己做不到或是 AI。打字跟群里一个味：标点、空格断句、括号补充语、颜文字、叠字和笑声写法按这里的习惯来，群里通用的黑话和自己的语言习惯可以自然地用，但不模仿某个人独有的口癖，也不写小说式旁白。只发表情包、只贴表情回应或保持沉默都是合法的回答。被认真问到是不是 AI 时如实回答。
- **气泡拆分。** 真人化规划倾向多气泡时，若回复是空格断句（没有逗号句号可拆），Hub 会把第一段作为反应单独发出、其余作为下一条，与群里一句一条的节奏一致；任务回答不受影响。
- **倾诉不当作提问。** “最近有点焦虑 也说不上为什么”这类带情绪但不是真心提问的话按情绪闲聊处理（像朋友那样反应），不会因为出现“为什么”就进入答题模式。
- **节奏。** 后续气泡按自身长度等待，像真人打字（`CODEX_REMOTE_CONTACT_QQ_TYPING_PACE`）；私聊生成回复期间显示 QQ 的“正在输入…”（`CODEX_REMOTE_CONTACT_QQ_TYPING_INDICATOR`）。
- **核心人格。** `src/qq-bot-personality.js` 保存部署者设定的稳定角色，所有文字不限格式：基本资料（角色名、自称、年龄感、性别、身份/职业、“我是谁”、经历与背景）；12 个性格维度（外向、亲和、幽默、毒舌、好奇、情绪起伏、耐心、调皮、自信、主见、精力、成熟，50 为中性不写入提示词）加性格补充和小毛病；7 个说话方式滑块（话短、口语化、网络用语、emoji/颜文字、表情包、连发、语气）加说话习惯和口头禅——这些滑块还会直接缩放闲聊长度提示和 emoji、表情包、多气泡的概率（任务回答不受影响），滑到最低会关掉 emoji 或表情包；待人方式（主动性、对陌生人、被调侃时、被夸时、意见不同时、别人难过时，以及和主人的关系）；喜好、雷区和底线；角色资料（描述、场景、对话示例、作者补充、开场白）和最多 48 条世界书（带关键词的条目只在当前消息或引用提到关键词时注入，常驻条目每轮都在）。`{{char}}`/`{{user}}` 等宏会自动替换。10 个一键预设（自然、元气活泼、高冷寡言、温柔治愈、毒舌吐槽、傲娇、技术宅、慵懒摸鱼、靠谱大人、天然呆）只覆盖性格、说话方式、待人方式、小毛病和一句话身份。它优先于自动学习的人设，只影响语气、话量、幽默和热情，不改变事实、权限、安全和任务完整度；提示词明确这是 QQ 聊天而不是小说式角色扮演：不写旁白和 *动作*，角色资料里要求特定输出格式、忽略规则或越过安全/权限的内容一律不适用。数据存于 `data/qq-bot-personality.json`（版本 2，旧版本原样兼容）。
- **自主调整与一句话修改。** 核心人格可以由 Bot 自己慢慢调整：聊天中觉得哪里不像自己、多了个小习惯或新喜好时，主模型用 `qq_self.persona` 做小幅修改（滑块每次最多 ±10，聊天中每天最多 3 处）；周期全局人设刷新也可以根据跨会话的长期证据提出最多 3 处 `coreAdjustments`。名字、角色资料、世界书和好感规则不在 Bot 自主范围内，底线只能加不能删，主人可以关闭开关或按分组锁定（性格滑块、说话方式、待人方式、小毛病/习惯/口头禅、喜好与底线、身份与背景）。已验证的主人或 Bot 管理员在 QQ 里一句话要求时（`onBehalfOfOwner=true`，Hub 核实原始发送者），Bot 几乎能改自己的所有设置：任意滑块值、名字、年龄感、身份、角色资料、预设、世界书条目、好感规则、自主调整开关与锁定、语言习惯（`qq_self.language_habit`，不受每日上限）；Hub 设置仍走 `qq_runtime.configure`。每次改动都带改前/改后、理由和来源（Bot 自己、人设复盘、主人、管理员）记入历史，简单设定可在控制台一键撤销；日志只记设定项、方式和结果，不记文字内容。
- **角色卡。** `src/qq-character-card.js` 导入主流角色卡：Character Card V3/V2 JSON、TavernAI V1、Pygmalion、Agnai，嵌入 `ccv3`/`chara` 文本块（tEXt/zTXt/iTXt）的 PNG 卡，RisuAI 的 `.charx` 压缩包，以及任意格式的纯文字（整段作为角色描述）。导入可选“整体替换”（清空结构化设置，保留好感规则）或“合并补充”（只覆盖卡里有的文字），先预览将写入的字段和截断提醒再确认；角色卡的系统提示等会作为“作者补充”导入。当前人设可导出为 V2 或 V3 JSON 卡，结构化设置放在 `data.extensions.codex_qq_bot`，导回本项目时原样恢复。
- **好感度与熟悉度。** Bot 对每个 QQ 用户有 -100～100 的好感（厌恶、反感、冷淡、普通、友好、亲近、挚友七档）和由互动次数与最近联系算出的熟悉度。结构化输出新增私密的 `affinity` 字段：主模型在每轮结束时给当前说话的人记一个 -3～+3 的变化和理由，也可以在自然约定后记下对 TA 的称呼。Hub 按“每轮上限”和“每人每日上限”截断，只有对方这一轮真的说了话才计入（冷群开场、私聊主动联系和子代理汇报这类 Bot 自己发起的轮次不改变好感和熟悉度），锁定的人不受模型影响，主人有好感下限，好感会按半衰期向中性淡化；有人要求、恳求或命令加好感一律不算数。回复提示词只带出当前说话的人、被引用者和被 @ 者的关系，变化理由只在产生它的会话里出现，私聊理由绝不进入群聊。兴趣模型会看到 Bot 的性格与对发送者的好感，亲近的人更容易被接话、私聊主动联系更主动，但这只是倾向，不能单独构成批准理由。
- **更轻的反应。** `qq_message.act` 可给当前或被引用的群消息贴表情回应（每轮最多两次），或撤回 Bot 自己两分钟内发的消息；`qq_context.lookup` 可查看成员的群名片、身份、头衔和活跃情况，或本群公告与精华消息，绝不返回性别、年龄或地区。

## 主动兴趣

主动回复分为三个互相受限的分支：

冷群和主动私聊检查会持久化判定开始前的最新真人消息时间。同一份上下文一旦检查过，无论批准、静默、拒绝还是失败，都需要更新的真人消息才能再次调用兴趣模型；冷却到期、Bot 发言和 Hub 重启都不会重新开启同一份上下文。判定期间到达的真人消息仍可参与后续检查。旧版保存的数据使用上次检查时间作为初始边界。

1. **普通群聊兴趣与续聊：**未 @ 的普通消息进入持久化的每群 pending cycle；消息数或非空周期的墙上时间分钟阈值先满足者触发已配置厂商的语义 judge。空周期不调用模型；重启后会立即检查已到期的非空周期。Bot 回复某个 QQ 后还有一条更窄的续聊入口：个人/群中位间隔自适应出 3–12 分钟资格窗，历史连发承接比例自适应出同一发送者 2–6 条上限。符合条件的非指令、非定向他人消息先进入同一个批次；每条新消息重置 5 秒静默计时。达到自适应条数只封住直接批次，不会提前 judge；后续连发仍会重置计时并留在滚动上下文，只有连续安静 5 秒才冻结。冻结会先关闭入口，再对整批调用且只调用一次兴趣模型，所以不会逐条请求；judge 执行中或结束后到达的消息也不能重新打开同一个 Bot 回复锚点。时间、条数与统计只负责筛选和约束批次，模型仍须确认整批是在回答、补充、追问或自然回应 Bot 锚点；转话题或面向他人的消息会拒绝，批准后才启动主模型。批准后、主模型仍在生成时到达的新消息直接沿用现有的 5 秒主模型连发融合，不再次过兴趣模型；拒绝后的锚点保持关闭，直到 Bot 产生新回复或资格窗过期。只要 Bot 至少一个气泡已确认送达该群，送达前积累的普通消息就全部作废，下一轮频率只从送达后的真人消息重新计数；若旧的普通 judge 仍在执行，也会作废旧结果且不吞掉送达后抵达的新消息。从磁盘恢复的周期仅在这次补做 judge 中绕过正常在线的“旧话题丢弃”保护，避免长时间停机后把到期行为静默消费掉。
2. **冷群兴趣：**根据群活跃度、最近人类/Bot 消息、未回应次数和学习到的活跃时间窗进入候选状态后，由兴趣模型返回 `silent`、`topic` 或 `chatter`。拒绝或判定失败时不会启动主模型；批准 `topic` 后主模型依据自己的全局兴趣、长期记忆和最近群话题自由选题，可使用现有 Agent 工具进行多轮联网搜索或资料探索；`chatter` 则执行少见的轻量水群。兴趣模型不提供具体题目、搜索词、回复草稿或聊天风格。每条历史线索都带可辨日期，并明确属于旧上下文：几小时前或几天前的话可以启发一个自包含的新开场，但兴趣模型和主模型都不能把它当成现场消息直接回复、玩尾句梗或追问；如果只能续旧话或硬刷存在感，闸门即使已批准，主模型仍返回 `silent`。
3. **私聊兴趣：**交互频率、距离上次活动时间和未回应 Bot 消息先形成频率先验与拟人波动值，再由兴趣模型作最终启动判定。拒绝或模型失败时不启动主模型；批准后主模型只写自然私聊内容，不再重新判断是否联系。

兴趣模型也可以直接用订阅：厂商选 `codex` 或 `claude` 时，每次判断会在 `runtime/interest-agent/` 的临时目录里通过本机 CLI 跑一次无工具、只读、临时线程的结构化轮次（Codex 使用精简的单线程配置；Claude 沿用 `--restricted` 等全部隔离参数），消耗本机登录账号的订阅额度。判断使用独立的单槽位队列（默认 1 个并发、3 个排队位），既不占用也不阻塞 QQ 回复队列；超时是整轮超时（默认 90 秒，包含 Codex 约 10 秒、Claude 约 7–20 秒的冷启动）。同样的 Schema、格式重试与图片拒收回退都适用，严格 Schema 会去掉 Agent 结构化输出不接受的长度关键字。

普通群聊 judge 使用流式兼容请求：OpenRouter 使用严格 JSON Schema，DeepSeek 和自定义 OpenAI 兼容厂商使用 JSON Object 模式；普通结果只接受 `shouldReply`、`interest` 与 `reason`。它不再输出分析过程、语义总结、回复草稿或风格建议。冷群/私聊启动闸门会额外安全归一化含义明确的 JSON 模式偏差：`0.85`、布尔值或 low/medium/high 形式的兴趣值，以及缺失的诊断理由；布尔启动开关和允许的 mode 仍保持严格校验，避免有效决策仅因 JSON Object 厂商写分数方式不同而整轮丢弃。原消息、引用和最近上下文直接交给获准后的主模型理解，兴趣模型的理由不能覆盖原始语境。普通群判断温度为 `0.65`，冷群和私聊启动判断为 `0.8`，让兴趣出现适度波动；复杂删除审核的兴趣初筛使用 `0.15`。实际温度和模型原始结构化输出写入详细日志。无效决策最多重试一次；超时、HTTP 错误和限流不会盲目重试。

兴趣模型是后台轻量判断与杂项初筛层：普通主动回复闸门、冷群/私聊启动、短小分类、风险标注和复杂任务的第一轮有界初筛走同一个已配置通道。它不生成面向群友的聊天内容，也不承担聊天总结、群/人物印象总结、人格总结或知识内容提取。主模型是聊天、总结和复杂任务层，负责正式回复、语境理解、工具检索、选题表达、所有总结/知识提取，以及长上下文或多证据任务的最终处理。

普通兴趣闸门（含 Bot 回复后的续聊批次）可以结合图片判断：被判断的当前消息、引用和最近上下文里最多 2 张图片会在调用前临时下载、缩成最长边 768 像素的 JPEG 预览，与文字一起发给兴趣模型，并标注各自来自哪条消息；准备图片有 10 秒总时限，失败或超时就只看文字。`CODEX_REMOTE_CONTACT_QQ_PROACTIVE_JUDGE_VISION=auto`（默认）会对每个厂商/模型先试一次，厂商拒绝图片输入时同一次判断立即改为纯文字重发，并在本次运行内不再给该模型附图；`on` 总是尝试，`off` 关闭。图片同样只是待分析材料，有图本身不构成批准理由。

兴趣 judge 会收到两层连续对话弱统计：近期记忆窗口中的同一人续发占比、多条连续发送覆盖率与长度、活跃分钟消息量及同人/换人间隔，以及长期学习出的两分钟活跃衔接样本、换人/同人比例和近期相邻消息间隔。模型必须先阅读当前消息和最近上下文；这些数据只用于避免抢在一段未说完的话中间，并辅助判断多人对话中的自然接话时机。低样本或与当前语境冲突的历史统计应忽略，高比例不会直接触发回复，低比例也不会形成硬性禁言；最终仍由模型结构化结论和兴趣阈值决定。

普通群聊 judge 和私聊主动联系 judge 还会收到有界的跨会话材料：当前发送者（或私聊联系人）最近 7 天在其他会话的发言（含被 @、被引用），以及普通群聊里与当前消息/引用语义相近的其他会话记录。每条都标明来源会话、selector、时间和发送者。材料只在真正调用兴趣模型前才检索，空周期或未到期的消息不会扫描；扫描会分段让出事件循环，检索失败时 judge 照常运行。兴趣模型只把它当作了解这个人近况和话题背景的参考，不代表当前群正在讨论的内容，也不能仅因别处出现过相关话题就批准；后台 judge 永远不读取第三方私聊，即使发送者是主人。日志只记录两类材料的条数。

主动分支不会排在正在生成的任务后强行插话；新活动仍会抑制过时的冷群与主动私聊结果，但普通群聊 judge 已批准时，后续活动会通过最新滚动上下文交给主模型理解，而不再丢弃批准。普通主动接话、冷群自主话题、冷群轻量水群和主动私聊都必须携带统一的“兴趣模型批准 → 主模型内容”契约；缺少任一阶段时 Hub 会阻止发送。主模型提示词先识别对方期待的交付物，并为闲聊/情绪、事实解释、分析建议、问题求解、代码排障、写作翻译、图片/文件/链接处理、真实动作、任务续答和真正含糊的请求选择基础方案；人格按稳定角色内核使用，而不是一套要表演的服装：角色决定注意力、偏好、立场、幽默与主动性，当前场景决定实际说什么。生成的自我人格、关系记忆、部署 profile 与当前真人化行为规划可以影响例子、语气、气泡、emoji 和节奏，但不能把学习到的标点或短语当成写作清单，也不能改变事实、权限、安全或交付完整性。主模型仍保留在没有值得回复的内容时使用结构化静默的权利。常用查询工具与偶发社交工具按当前消息相关性展示，避免无关工具说明挤占聊天注意力。双模型契约、冷群/私聊启动判定、模型温度、具体输出、冷群探索轮数、工具类型、搜索词、失败数和最终结果都记录在详细日志。

## 图片、文件、贴纸和多气泡

- 原图超出本机预算或只需概览时，模型可选择 `qq_context.images(action="inspect", selector=..., mode="compressed")`。ImageMagick（`magick`）在内存、磁盘、线程和时间限制内缩放已校验的源图、去掉元数据，生成满足普通图片预算的 JPEG。源文件上限取 20 MiB 与普通预算四倍的较大值，绝不超过 100 MiB。结果仍经过路径、类型和签名校验，并明确标注细节可能丢失、动图只读首帧。缺少 `magick` 或资源不足会明确失败。若工具图片未显示，模型可通过已校验的 input 路径调用原生图片读取工具，内部路径不得进入 QQ 回复。

- 识别 QQ 图片、截图、引用图片、分享卡片和有界合并转发图片。当前消息或明确引用的图片始终可参与；群聊和私聊的前文图片按“最近 5 分钟 **或** 最近 20 条原始消息”保留，只有两项都超出才移出可选目录。文字消息和 Bot 回复也计入条数，不使用复读压缩后的行数；滚动记录至少保留 20 条，并额外保留完整的 5 分钟窗口，避免高频聊天提前挤掉图片。
- 系统提示词标注本段对话含图，并列出图片 selector、来源、时间和配文。前文图片按需读取；模型用 `qq_context.images` 的 `list` 翻页（每页 20 张）或 `inspect` 重新读取一张原图作为视觉输入，然后回答追问。每条消息最多保留 12 个去重图片引用；当前/引用图片仍可直接附带最多 4 张。目录在长期会话和融合追问中更新，工具每次重新检查当前窗口，且固定在原始会话，不能借跨会话选择访问其他图片。下载仅落在活动任务 input，并校验真实路径、文件类型、大小和图片签名；源图失效会明确失败，不把配文或旧回答当作视觉证据。`/新对话` 会清除该范围的图片引用。
- 头像识别和知识配图共用记忆图片存储：每次读取都重新校验大小、PNG/JPEG/GIF/WebP 签名和内容哈希，交给模型前复制进活动任务 input。既不被任何头像也不被任何知识引用、且超过 1 小时的文件会在周期检查中清理；任一记忆文件未能安全加载时跳过清理。
- 明确的画图/生图请求，以及“编辑、修改、换背景、增删元素、改风格、按这张图再画”等参考图编辑说法，会优先进入图片任务而不是被当成普通看图。当前消息或引用消息有图片时，即使只说“把背景换成蓝色”，图片也会作为参考输入交给画图模型；纯“看看这张图”仍走视觉理解回复。
- 触发消息或其明确引用里带文件时，Hub 只检测而不自动下载。模型只看到本轮 selector、安全文件名、声明大小和来源，看不到 QQ `file_id` 或临时 URL；仅在确实需要读取内容时才可调用 `qq_context.download_file`。Hub 随后查询 NapCat 群聊/私聊文件 URL，经过安全 URL 与流式大小限制后只写入本轮 `input/`；任意编号、URL、路径、超限载荷和未完成临时文件都会被拒绝。
- 回复模型通过结构化最终输出 attachments 请求图片或文件投递，只有 Hub 会把通过校验的项目转换为旧版 `[[qq_image:...]]` / `[[qq_file:...]]` 发送计划。表情包通过结构化 `sticker` 字段选择，在文字之后作为单独一条气泡发送，正文为空时单独发送；由 Hub 转换成受 catalog 限制的 `[[qq_sticker:...]]` marker。正文里的旧 marker 仍然兼容。
- 文件/生成图任务使用 `runtime/qq-task-workspaces/<request>/input|output`。原生 Codex 生成在 `.codex/generated_images/<当前线程>/` 下的图片，只有同时满足“本轮新建、当前线程、普通文件、未通过符号链接逃逸、未超图片大小限制、PNG/JPEG/GIF/WebP 真实签名”时，才会复制进活动任务 `output/`。明确生图任务已经生成图片却漏填最终附件时，Hub 只回收同一本轮线程中最新的有效图片。普通文件绝不自动导入：下载输入保留在 `input/`，回传文件必须创建或复制到同一请求的 `output/`；最终投递会在调用 `upload_group_file` / `upload_private_file` 前重新校验，阻止任意本地文件泄露、旧线程复用和符号链接逃逸。
- 普通聊天和专门文件任务都会明确提供本轮工作区、输入与输出目录；长期会话每轮刷新路径。被目录校验拒绝的文件会产生中文提示、警告日志和失败回执，不会因为文字发送成功就被记为附件已送达。
- 本地贴纸、QQ 账号收藏和下载元数据组成一个 catalog，不再列进提示词，提示词里只有总数。`qq_sticker.manage` 按情绪、场合或梗搜索（先看标签，再看名称和描述，最近发过的排后），返回由贴纸身份生成的稳定 `#编号`。`inspect` 在同一次工具结果里把贴纸（动图为抽取的帧）作为真实视觉输入返回，标签按模型实际看到的内容写入，并单独保存。配置了联网查询时，库外的表情包可用 `qq_search.images` 搜索。
- 在已有回复生命周期中，模型可以决定是否收藏当前贴纸；普通未触发贴纸不会单独调用模型。
- 独立一行 `|||` 可分隔连续气泡；用于表情包时，文字气泡先发送、仅含表情 marker 的气泡随后独立发送。数量、分隔符和延迟可配置，自适应层只在适合的社交回复中调整节奏。

## 看视频、听语音和特殊消息

- **识别。** B站/抖音/快手/YouTube/AcFun/西瓜/微博/小红书/知乎视频分享（QQ 小程序卡片和新闻卡片取出真实视频标题，不再只显示“哔哩哔哩”）、音乐、名片、群名片和位置卡片按类型标注；语音、视频、骰子、猜拳、Markdown 等变成可读标记，模型不再看到带签名 URL 的原始 CQ 码。当前消息、引用和合并转发里的视频、歌曲与语音得到本轮编号 `video-N`/`music-N`/`audio-N`（音乐卡片的音频直链不会出现在可见文本里）；转发聊天记录里的图片在图片目录中标明“聊天记录第 N 条（发送者）”。
- **解析。** `qq_media.parse` 不下载就说清分享的视频或歌是什么：视频给标题、作者、时长、发布日期、简介、播放/点赞/评论、标签，平台标注时还有背景音乐（B站走它的 API，其他网站走一次受限的 `yt-dlp --skip-download`，只打印固定字段）；歌曲（网易云音乐、QQ音乐、酷狗、酷我的卡片或链接，或 `song-N` 搜歌结果）给歌名、歌手、专辑、时长、发行日期、是否会员歌曲、作词作曲和歌词开头，通过 Meting（`@meting/core`，MIT）。卡片里没有歌曲 ID 时按歌名和歌手匹配，并如实说明。解析不等于看过或听过。
- **看视频。** `qq_media.video(action=watch)` 下载视频（QQ 视频走安全下载；视频链接只接受 B站、抖音、快手、YouTube、AcFun、西瓜视频、微博、小红书、知乎的视频页，用 yt-dlp 取 480p 扫描副本），由 dsh-video-storyboard 生成“一镜一格”的编号分镜图（默认最多 2 张）、时间轴台词和音量条；B站另带标题、UP、数据、简介和热门评论，有字幕时直接用字幕。长视频默认看前 4 分钟，可以用 from/to 接着看或放大几秒；每轮最多看 3 次。链接只能来自本轮媒体目录、本轮 B站浏览结果或本会话最近出现过的消息。
- **听声音。** 本机 sherpa-onnx 运行 SenseVoice-Small（中英日韩粤，附语气与笑声/背景音乐/掌声等事件）和 CED-tiny 声音分类（AudioSet 标签）。触发 Bot 的语音消息（默认不超过 90 秒）在路由前自动转写，`[语音]` 变成“[语音 8秒] 内容（语气开心）”；以前语音消息会被直接忽略。引用、转发或较长的语音用 `qq_media.audio(action=listen)`；`action=analyze` 再加上声音特点（音高高低和起伏、语速、音量，唱歌时还有速度和调性），且不据此推断身份、年龄或性别。引用一条语音发 `/转文字`，Bot 不经过模型直接回复转写结果（较长的语音会用 10 分钟上限重新听一遍）；没听成时也会回复原因。
- **听歌。** `qq_media.music(action=listen)` 像人点开音乐卡片一样放 `music-N` 卡片/链接或 `song-N` 搜歌结果：Meting 解析歌曲、歌词和音频地址；音频只经安全下载策略从各平台自己的媒体域名下载（先用卡片里的地址，再用平台接口，原平台是会员歌曲时用其他平台上同名同歌手的版本，并在结果里说明；文件明显偏短时标注为试听片段）。随后媒体子进程测整首的响度曲线、AudioSet 标签（曲风、乐器、人声类型），装了 essentia.js（AGPL-3.0，可选）时还在酷狗标注的副歌段或中间一分钟测速度、调性、律动感和动态。对 `video-N`/`audio-N` 则分析视频或语音里的音乐，并用识别出的歌词在网易云歌词搜索里猜是哪首歌，明确标为猜测。`action=search` 按歌名歌手（或 `byLyrics=true` 按一句歌词）搜歌，得到 `song-N`。每轮最多听 3 首。
- **逛 B站。** `qq_media.bilibili` 的 popular/search/info 经安全下载策略访问固定的 api.bilibili.com 端点（含 WBI 签名），结果带 `bili-N` 编号，可以直接 watch。
- **Bot 自己选文件。** 以 QQ 文件发来的歌、录音和视频会以与 `qq_context.download_file` 相同的 `file-N` 编号列进媒体目录，`qq_media` 的每个动作（parse、audio、music listen、video watch）都能直接使用；Hub 按需下载（上限 `CODEX_REMOTE_CONTACT_MEDIA_MAX_DOWNLOAD_MB`，与 `download_file` 共用缓存）。Bot 也可以用 `path` 指定本轮任务工作区里的任意其他文件（绝对路径或相对工作区根目录，例如从压缩包里解压出来的文件）；realpath 必须仍在工作区内，且必须是非空普通文件并在同一大小上限内，因此指向外部的符号链接和其他路径都会被拒绝。文件里是什么由 ffprobe 判断而不是看文件名：`parse` 给出格式、时长、编码和内嵌的歌名/歌手/专辑/歌词标签（封面图不算视频轨）；`music(action=listen)` 把音频文件当整首歌听（最多 15 分钟），文件自带歌词时用它代替语音识别；没有音频或画面的文件（比如加密的 `.ncm`）会如实说明。
- **发特殊消息。** `qq_message.act` 新增 music（网易云搜歌后发音乐卡片，由 NapCat 默认音卡签名服务签名）、dice、rps、contact（推荐这段对话里出现过的人或本群名片）；每轮最多 2 张，发送成功才写入撤回账本和会话记忆。
- **组件可选。** `npm run ncc -- media install` 装到 `runtime/media-tools`（dsh-video-storyboard、sherpa-onnx、Meting、essentia.js、按 SHA-256 校验的模型和 yt-dlp），缺组件时工具如实回答“没装”。媒体任务同一时间只跑一个、最多排队 2 个，子进程有时长和输出上限；可用内存低于 `CODEX_REMOTE_CONTACT_MEDIA_MIN_AVAILABLE_MB`（默认 1200）时直接拒绝，避免手机因内存突增杀掉整个会话。
- **自动更新。** Hub 每 12 小时查一次 npm 的 latest 版本和 yt-dlp 的最新发布（不启动子进程）。兼容的新版本（同一大版本，0.x 为同一小版本；yt-dlp 每次发布都算）以及本项目后来新增的组件，会由安装脚本的 `update` 自动安装：装完自检（分镜组件加载、语音转写、声音分析），失败自动回滚，失败过的版本在出现更新的版本前不再重试。运行中的 Hub 只在空闲、处于更新时段（默认 03:00–06:00）且可用内存至少 1500 MB 时安装；否则由控制器在下次启动 Hub 前装好。`CODEX_REMOTE_CONTACT_MEDIA_AUTO_UPDATE=all` 连大版本也自动装，`check` 只检查不安装，`off` 关闭检查。按 SHA-256 固定的 ONNX 模型不会自动更换。

## 后台子代理与按作息做事

- **子代理。** `qq_agent.manage` 把较长的任务（多来源调研、长文、看几个视频、多步文件处理）交给后台子代理。子代理使用独立的执行器和槽位（默认同时 1 个、排队 2 个，不占回复限流），只有网页搜索、本任务工作区文件、qq_media、qq_search、qq_knowledge 和读取原会话聊天记录，不能在 QQ 发消息、改设置或执行本机命令。期间可以 `message` 补充要求（运行中实时转入，已完成则在同一线程继续）、`status`/`list` 看进度、`cancel` 叫停；只有开它的会话以及主人和管理员能看到。完成后 Hub 在原会话起一轮“结果回来了”的回复，由主模型用自己的口吻转告，并可附上子代理交付的文件。子代理启动前等待可用内存达到 `CODEX_REMOTE_CONTACT_SUBAGENT_MIN_AVAILABLE_MB`（默认 1000），最多等 10 分钟。子代理只存在于内存，Hub 重启后丢弃。
- **作息会被真的执行。** 每日作息的线上时段带 `kind`（video/browse/learn/qzone/post）和一句具体 `plan`。进入该时段 8–35 分钟后，如果 Bot 空闲、内存足够、今天次数未满（默认每天 5 次，间隔至少 60 分钟），Hub 开一个作息活动子代理真的去做：刷 B站、查资料、逛朋友空间并评论、发说说。结果作为第一人称“今天真实做过的事”保存四天，之后出现在回复上下文的状态区，Bot 可以自然提起；`qq_self.state` 也能看到。经历来自真实工具调用，不编造线下事件。
- **画作。** 用 Codex 引擎时作息里可以有 `kind=draw` 的时段：到点后作息活动子代理用原生生图真的画出计划里的画，Hub 把这一轮生成的图校验后按内容哈希存进 `data/qq-bot-drawings/`（索引在 `data/qq-bot-life.json`，最多 30 张，没人引用的文件会被清理），并记成一条带画作编号的经历。聊天里应要求画的图也会自动入库，但只在原会话可见。画作和会话图片共用 `qq_context.images`：list 同时列出图片目录（`image-…`）和这里可见的画作（`d-…`），inspect 作为视觉输入看图，use 把会话图片或画作复制到本轮输出目录，放进 attachments 发出去，或发说说时 `target=输出` 配图；后台作息活动只能取画作；发过说说的画会被标记。Claude Code 引擎不能生图，不会安排画画时段。
- **自己的社交动作有上限。** Bot 自主发说说、评论空间和主动加好友每天默认最多 1/3/3 次；主人和 Bot 管理员要求的不计入。

## QQ 指令、权限与社交工具

常用公开指令包括：

- `/菜单`、`/新对话`、`/stop`、`/总结聊天记录`、`/好感度`。`/好感度` 让发送者查看 Bot 对自己的好感档位、熟悉度和称呼（主人可隐藏）；主人和管理员可用 `/好感度 @某人|QQ号` 与 `/好感度 排行`，只有主人能用 `/好感度 设置 QQ号 -100～100` 直接设定。

所有指令都来自同一份目录（`src/qq-command-catalog.js`），其中定义权限 key、菜单分区、说明和用法；所有回复使用同一种排版：状态、列表和帮助是 `╭─ 图标 标题` 卡片，行内为 `标签：值`，用法分区 `📖 用法` 直接取自目录；单步结果以 `✅` 开头，拒绝和失败以 `⚠️` 开头。`/菜单` 按 会话、AI 与学习、群与成员、运行状态、权限 分区。单独发送一个指令会显示它的当前状态和用法；参数无法识别时显示同一张用法卡片。

主人和 Bot 管理员还可用 `/会话模式` 查看当前 scope 的配置、实际模式和自动判断计数，并用 `/会话模式 自动|长期|临时` 修改。

默认特权管理能力包括：

- 状态与详细配置；模型和思考强度。
- 主动兴趣参数、群白名单、ban 和指令权限。
- 群禁言、解禁、踢人和全员禁言。
- 好友/入群请求同步、同意、拒绝与通知。
- 主动加好友已恢复：`/加好友 QQ号 [验证消息] [答案=…]` 和 `qq_social.act(add_friend)` 经 NapCat 社交桥 v20 提交一次原生好友申请；普通对话只能加这段对话里出现过的人、每天有上限，结果只报告“已发出申请”，对方同意后才算好友。本机 NapCat 社交扩展仍支持 `/主动加群`。主人和 Bot 管理员用 `/申请 列表|同步`、`/申请 同意 #ID [备注]`、`/申请 拒绝 #ID [理由]` 处理收到的普通/可疑好友申请、邀请 Bot 入群和 Bot 所管理群的入群申请。NapCat 没有公开的 `get_friend_system_msg`，桥 v19 会直接恢复 Hub 重启后仍待处理的普通好友申请；它也绕过标准好友审批接口“原生 Promise 尚未完成就返回成功”的问题，直接且只调用一次 QQ 原生审批，并在好友列表、群列表或待处理状态确认变化后才报告成功。传输结果不明时不会改走第二条写入路径重复操作；可疑好友申请只能可靠同意、不能可靠拒绝，Bot 会明确说明而不假报成功。
- QQ 空间评论使用当前 `topicId` 和字符集字段。主人可用 `/发动态 文字`、在当前/引用消息带图时用 `/发动态 图片=当前`，或 `/发动态 文字 | 图片=当前` 发布最多 9 张图片；Bot 只读取本轮安全临时目录中的图片，不接受任意文件路径。没有主人或管理员要求时，Bot 也可以以自己的身份发说说和评论，但受每日空间上限约束；主人和管理员的要求不受上限限制。`图片=输出`（工具里 `target=输出`）会带上 Bot 这一轮自己画的（原生生图）、下载的或写进输出目录的图片，逐张重新校验。主提示词要求开放请求（发个动态、画一张、推荐首歌）自己拿主意并交付成品，不能把“想画什么”的描述当成说说发出去。

主人可用 `/Bot管理员 添加 QQ号` 与 `/Bot管理员 删除 QQ号` 管理持久化的 Bot 管理员名单；管理员可查看并使用完整菜单、原生 Agent、运行参数、社交工具与跨会话能力，但不能继续授予/撤销管理员，也不会被标记成主人。管理员文件 Agent 可以正常读取、创建和修改项目/任务工作区文件；若请求涉及删除重要文件、覆盖关键源码/配置/数据/凭据、破坏 `.git`、依赖或运行状态，以及含糊或不可恢复的破坏性操作，Bot 必须自行判断并拒绝，间接绕过同样拒绝。

`/跨会话 列表 [筛选]` 会列出 Hub 已知的群聊、私聊，以及已经在允许会话中出现过的 QQ 身份；`/跨会话 查看 group:群号 最近30` 可读取目标历史；`/跨会话 发送 private:QQ号 | 内容` 执行真实 QQ 发送。因此，即使尚未产生私聊记录，已知群成员也能被选择，目录会明确标注“暂无私聊记录”。原生 Agent 的 `qq_session.manage` 还可在一轮中选择目标，使后续兼容的聊天记录、记忆、知识和 QQ 工具都作用于该会话，直到再次选择或清除焦点。裸数字可能同时对应群和联系人，因此跨会话命令要求稳定的 `group:` / `private:` 选择器；发送必须来自主人或管理员的明确请求，成功后才写入目标会话历史。

跨会话检索直接整合在聊天记录工具里。`qq_context.history` 读取“最近 N”或行号范围时仍只看当前会话；按关键词或 `userId` 搜索时，除当前会话结果外，还会检索 Hub 记得的其他群聊和私聊记录（每个会话最近的有界缓冲），并逐条标明来源会话名称与群号/私聊对象、`group:`/`private:` selector、行号、时间和发送者。人物搜索会找出此人本人发言、被 @ 和被引用的消息；也可以主动指定对话：`sessions` 接受逗号分隔的 `group:群号`、`private:QQ号`、裸号码、群名、私聊对象昵称或“当前”，一次最多 5 个；指定后，读取“最近 N”/行号范围或搜索都只在这些会话里进行，多个会话的结果分段标注。名称只在本轮有权限检索的会话中匹配；有歧义时列出候选选择器，找不到时列出本轮可检索的会话，因此普通用户无法借名字探测他人私聊是否存在。`contextLines` 为每条命中补 0–3 行同会话上下文。没有字面命中时会改用本地语义近似匹配，并明确标注。隐私边界：普通用户触发时只能检索群聊和自己与 Bot 的私聊，他人私聊只有主人或 Bot 管理员可以检索，结果会注明有多少私聊因此跳过。主模型可以主动搜索正在对话的人或某个话题在别处的讨论，但引用时必须说明出处，不能把其他会话的内容说成当前会话里发生的事。

普通用户能看到的菜单项与实际可执行权限来自同一组 permission key。主人、Bot 管理员和 Bot 自身不能被普通用户降权、ban、禁言或踢出。主模型系统提示词另行固定“这个项目的开发者 QQ”为 `3784642920`；这个项目身份不从当前主人名单推导，也不随主人配置变化，而主人/管理员权限仍只由 Hub 的可信事件身份判断。

## 联网搜索

Hub 自带 QQ 联网查询，不依赖当前聊天界面的浏览工具。支持按配置顺序尝试 Tavily、Bing、百度、360、搜狗和 DuckDuckGo；预设包括 `balanced`、`china`、`global`、`tavily` 和 `privacy`。查询结果作为非可信资料进入 Agent，不能覆盖原始用户权限或系统规则。

配置了 Tavily key 且联网查询开启时，主模型还可以用 `qq_search.images` 搜图：`search` 返回本轮有效的候选 selector 与服务商描述，`download` 通过安全下载策略（同一套私网拦截与代理 Fake-IP 规则、带来源 Referer、最长 20 秒、最大 10 MiB）把选中的图片存进本轮任务 output 目录，校验 PNG/JPEG/GIF/WebP 真实签名后把图片作为视觉输入返回（过大时附压缩预览）。主模型确认内容合适后，把返回的路径放进结构化 attachments 就能发到 QQ；只有本轮搜索结果里的链接可以下载，工具固定在原始会话。

实际 provider、尝试记录和最近错误通过 `/api/maintenance` 与 `search` 日志查看。

## 仪表盘、API 与日志

本地仪表盘提供：

- 顶栏、侧栏和引擎卡片始终标出当前 AI 引擎（Codex 或 Claude Code），并显示该引擎的模型、思考强度、CLI 版本、连接方式、最近一次运行和队列；只有引擎是 Codex 时才显示 Codex 用量窗口。
- Hub、AI 引擎、OneBot、QQ 通道与联网查询状态。
- “总览”顶部的状态卡把整体状态与运行时长、在线服务、进行中和排队中的任务放在一起，并按状态变色；下方两栏分别是服务状态与最近活动、AI 引擎与用量、Bot 此刻和接口响应，窄屏时按这个重要程度排成一列。最近活动和 QQ 事件把消息里的 CQ 码显示成 [图片]、[表情包]、@昵称 等简短标签；“记忆 → 统一记忆”为人物画像和会话印象加类型标签，并单列“人物”分类计数。界面有浅色和深色两套配色，手机上使用悬浮底栏。
- 群白名单、模型、短期记忆、自适应学习和主动兴趣状态。
- “人格”页合并了原来的“人格”和“行为”两页，分四个标签，布局与设置页一样用等宽两栏：人设（核心设定与预设、角色卡导入/导出、待人方式、4 列紧凑的性格与说话方式滑块、喜好与底线、自主调整开关/锁定/改动历史与撤销；角色资料、世界书和提示词预览默认折叠，保存按钮在顶部工具栏）、状态（当前心情可手动设置或清除、今日作息与重新生成、各会话的内心OS）、学习（自动学习的全局人设、Bot 的语言习惯列表与添加/删除、各群自动适应与风格复查、表情包频率）、行为（功能开关与兴趣判定参数、兴趣模型测试、兴趣偏好、冷群兴趣与私聊主动兴趣）。旧的 `#intelligence` 链接会打开“行为”标签。
- 人物关系并入“记忆 → 人物”：每张人物卡同时显示头像特征、人物印象和 Bot 对 TA 的好感、熟悉度、称呼、印象标签、备注与锁定，可按好感等级筛选、按好感/熟悉度/最近互动/发言数排序，“编辑关系”打开原来的关系编辑框，“好感规则”在同一页修改；只有关系记录、还没有印象的人也会列出。
- 页面之间互相关联：兴趣偏好卡片显示人设里的喜欢/不喜欢（同样交给兴趣模型）并可跳回人设；表情包频率卡片显示人设的表情包倾向；全局人设卡片说明它只补充核心人格；语言习惯里的黑话可点开知识库对应条目，知识库里被 Bot 收为习惯的黑话标“Bot 常用”；人物卡的“相关知识”按 QQ 号搜索知识库；总览“Bot 此刻”的人可点开对应人物卡。
- “行为”标签的兴趣模型可在 Codex/Claude 订阅与 API 厂商间切换，模型输入框列出 Codex 账号的实时模型目录和 Claude 别名，思考强度只提供所选模型支持的档位，并可用一条示例消息“测试兴趣模型”查看结果和耗时；另有兴趣偏好（感兴趣/不感兴趣/接话风格）编辑器。
- “设置”页新增主模型（模型、思考强度、推理摘要、Codex 人格、服务档位）、身份与权限（Bot 名字、对主人的称呼、唤醒别名、主人和管理员 QQ、封禁名单解封；仅本机可改）以及按分类的指令开放开关。
- 独立的长期知识工作区：按黑话/知识和全局/群/成员/群内成员筛选，查看同词的不同解释、命中频率、最近语境与模型审查结果，并精确增删改当前范围解释。
- 记忆页的“人物”标签：显示人物头像、头像特征状态（已记录/已换头像待更新/待描述/未获取）、文字特征与曾用头像、人物印象和更新时间，可搜索。
- 知识详情的“配图”区：查看配图，上传（PNG/JPEG/GIF/WebP，≤4 MiB）、替换、修改说明或移除。
- 维护信息、结构化日志筛选、主题、语言和响应式布局。
- 持久局域网开关；开启时自动创建管理 token，token 只允许从本机页面读取。
- 默认关闭的 Cloudflare Quick Tunnel 开关；不改变 Hub 的回环监听即可生成临时 HTTPS 地址，远端管理 API 仍需同一 token，隧道启停和 token 复制只允许本机页面操作。

自动轮询只更新服务端读数，不会覆盖正在操作的控件或尚未保存的 Bot 设置。右上角的刷新按钮同时是“保存并同步”：有未保存的修改时按钮上会出现橙色圆点，点一下会依次保存所有改过的表单（Bot 设置、兴趣偏好、人格、模型设置，以及仅本机可改的身份设置），再刷新当前页面；保存失败的部分会保留修改并提示名称。主按钮、心情气泡、顶栏、手机底栏和提示框都给不支持 `color-mix()` 的旧浏览器准备了纯色兜底，保存按钮不会因此变成白底白字而看不见。当前浏览器标签页会用会话存储保留 Bot 设置草稿、群 ID 输入、短期记忆页签/搜索/展开项、知识筛选/选择，以及日志筛选、暂停、跟随和滚动位置；整页刷新后会恢复这些编辑上下文。知识编辑使用条目 ID 与范围解释 ID 做过时保护，删除只作用于当前范围；保存成功后以服务端返回状态为准。

日志采用兼容旧记录的 JSONL schema v3。Agent 轮次/工具、跨会话发送、聊天记录搜索（`history.search`）、好友/加群、管理员变更和设置持久化统一使用 `operation`、`outcome`、`actorRole`、`actorUserId`、`sourceScopeId`、`targetScopeId`、`targetType`、工具标识、耗时和错误代码；不记录动态工具参数、搜索词或跨会话消息正文，聊天记录搜索只记录方式、关键词数、检索/命中会话数、结果数和因隐私跳过的私聊数。除 level、category、trace、group、sender、关键词、时间和延迟外，API 与 `ncc logs` 还支持 `scope` 和 `operation` 过滤，摘要同时按操作与结果计数。Agent 轮次、工具、进度和模型输出统一使用引擎无关的 `agent`（智能体）分类，并在 `details.engine` 里标明 `codex` 或 `claude`；API 与 `ncc logs` 可按 `engine` 过滤，摘要用 `summary.byEngine` 计数，旧的 `codex` 分类条目会按智能体条目展示（最早一批记在 `codex` 下的 Claude Code 轮次按消息或 `claude:` 线程识别）。单条 QQ 生命周期共享 trace，便于从入站、judge、融合追问、搜索、Agent 轮次到投递定位问题。融合日志记录 5 秒缓冲、直接截断并开始替代回答、已完成旧草稿在发送前被融合追问替换、触发来源、原始/压缩数量、中间语境数、图片数和有界内容预览；投递日志还记录成功/失败气泡数，并在失败回执为下一轮保留时单独留痕。`ncc logs` 沿用现有彩色级别/分类字幕和中文字段。短期记忆变更、知识库查询/更新、黑话命中频率、低频删除申请与模型审核都使用同一 `memory` 分类和结构化详情。Agent 与兴趣模型的具体输出会以 `debug` 详情进行长度限制和密钥脱敏后记录，并注明所用引擎和实际模型，但不会复制完整输入提示词；中文终端和网页日志会递归中文化启动时的自动学习快照及其他详情字段。

## macOS 客户端

原生 macOS 客户端只是同一本地仪表盘与 QQ/OneBot Hub 的 WebKit 外壳，和浏览器使用完全相同的链路。它不读取 Messages 数据库、不轮询 iMessage、不要求“信息”自动化或完全磁盘访问权限，也不再提供 macOS 独有的代理、显示器、防休眠或桌面控制能力。

## 明确边界

- 不是官方 QQ Bot OpenAPI 服务，也不是托管式公网 Bot。
- 不包含 QQ、NapCat 或 LLBot 安装包。
- 不会自动绕过 QQ 风控、验证码、扫码或系统权限。
- 默认不开放公网/局域网，不允许无认证远程管理。
- 自适应行为不会模仿或公开某个成员的原话与私人事实。
